# ROOTS roadmap

## Version 1

Version 1 includes the ROOTS foundation, universal local profile, deterministic dietary engine,
barcode and label scanning, crop/review, resilient processing, final reports, local history and
Saved products, existing AI tools, PWA offline shell, and production hardening.

## Version 2

Phase 4A begins Version 2 with two controlled changes only: a flat smartphone-camera Home
animation and one customizable canonical Jain profile. It adds no restaurant, location, account,
payment, or cloud behavior.

## Later Version 2 candidates

These are explicitly outside Version 1 and require separate product, privacy, API, and testing
specifications:

- Restaurant discovery and menu scanning
- Accounts and optional family/cloud sync
- Product alternatives
- Expanded AI recipes and meal planning
- Notifications
- Analytics with explicit privacy review
- Payments or premium features

Phase 4B provides location, meal intent, provider abstraction, local recents/saved locations,
restaurant-list caching, and honest restaurant cards.

Phase 4C provides source-aware menu retrieval/import, OCR, translation, deterministic structural
parsing, correction, freshness, and normalized local storage. It does not evaluate food.

Phase 4D consumes the documented menu-evidence contract through a deterministic evidence graph,
profile-rule trace, supported modifier engine, and four explainable dish verdicts. It does not
infer ingredients absent from menu evidence and uses no AI for compatibility.

Phase 4E adds deterministic, evidence-first personalized restaurant ranking, match categories,
cards, sorts, filters, detail explanations, and three-restaurant comparison. It adds no ordering
assistant and uses no AI to rank.

Phase 4F-A is complete: dish detail, deterministic Build My Order, complete-meal component
selection, live evidence aggregation, comparison, portion awareness, local Save Meal foundation,
and order review. Restaurant memory, server questions, and voice remain intentionally unstarted.

Phase 4F-B is complete: versioned Saved Meals, distinct Order History, personal location/dish
notes and confirmations, Order Again with deterministic current recheck, change/staleness
detection, Saved and restaurant-detail memory, local search/filter/sort, archive/delete,
copy/share privacy, and offline access. Phase 4G server questions, translations, and voice remain
intentionally unstarted.

Phase 4G-A is complete: deterministic evidence-linked server questions, priority/category grouping,
copy/share, validated translation with offline cache, device speech, printable question sheet,
saved question sets, and accessible restaurant communication. The signature visual Dining Card
remains reserved for Phase 4G-B.

Phase 4G-B is complete: Ask ROOTS on restaurant and dish pages, guarded evidence-cited
explanations, simple and technical modes, an expandable evidence Decision Tree, session-only
conversation, structured staff-response evidence, phone/print/light/dark Dining Cards, strict card
translation, copy/speech/print, and the local Restaurant Glossary and Ingredient Explorer.

Phase 4G-C is complete: manual Travel Mode setup, destination language suggestions, versioned
offline packs, allergy-first profile cards, exact Jain-option phrases, original/translation/
transliteration preservation, device speech controls, regional glossary and aliases, offline
cards/questions/phrases, private IndexedDB storage, separate deletion controls, and Home animation
size/flash/canonical-package corrections.

The next phase should focus on real-device travel QA and curated language review rather than new
restaurant compatibility features.
